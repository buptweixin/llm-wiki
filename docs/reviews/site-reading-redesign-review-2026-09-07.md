# 站点阅读改造验收报告

日期：2026-09-07  
审查提交：`b35b7b2`（`redesign knowledge site reading experience`）  
对照：[改造 spec](../specs/site-reading-redesign.md)  
结论：**需要修改。连续阅读和专题入口已经建立，全文查找、回忆交互、内容准确性和后续维护尚未达到第一版验收标准。**

本次只审查并记录结果，没有修改站点实现、知识正文、复测记录或发布线上版本。

## 1. 审查范围与证据边界

- 阅读本次提交的共享 CSS、JS、静态索引、首页、论文页改动、模板和标签词表；与 Markdown 真源及现行维护规则对照。
- 使用 Chrome 打开本地 `file://` 站点。首页与 U-OPSD 做桌面观察；九篇论文均检查 390px 窄屏的页面宽度、滚动设置和旧锚点是否存在。
- 实际操作搜索、标签筛选、问答展开、回忆模式、两篇比较和键盘焦点。
- 未验证 Safari、实际 iOS 浏览器、200% 缩放和线上认证后的新版本；不把这些项目标为通过。
- 提交还包含之前已写好的 spec 和已有复测记录，不能把提交里的所有行数都归因于此次站点实现。

## 2. 已达到预期的部分

1. 九篇页面的正文滚动吸附均为 `none`；旧的全局方向键整节跳转已移除。
2. 九篇页面在 390px 检查中，文档宽度未超过视口；宽表使用局部横向滚动。
3. 四个研究专题已进入首页，能够通过筛选缩小论文范围。
4. URL 查询状态和 `popstate` 处理已实现，搜索词输入使用 `replaceState`，筛选使用 `pushState`。
5. 现有九篇的 `slide-1` 至 `slide-7` 旧锚点仍存在，同时增加了章节目录。
6. 普通阅读状态下，问答可以折叠与展开；浏览器不会自动写入“已掌握”结果。
7. U-OPSD / S²VOPD 比较弹窗可以打开和关闭，明暗主题都有对应样式。

这些是有效改进，应在修复中保留。

## 3. 必须修复的问题

### R1 · P1：新增检索文本引入了与真源相反的机制解释

**位置：** [wiki-index.js](../../site/assets/wiki-index.js) 第 118 行；[Open-MOPD 真源](../../wiki/papers/2026-open-mopd.md) 第 53～56 行。

索引的卡壳片段写成：

> 更新教师分数只是复用这次计算。

Markdown 明确记录：教师冻结，教师 logprob 可缓存；刷新的是学生项，复用 PPO 本来就会算的当前学生 logprob。网页新增内容把更新对象写反，会损坏用户已经建立的理解。

另外，[比较数据](../../site/assets/wiki-slides.js) 第 175～181 行把“文本推理额外信息可恢复”放进 U-OPSD 的训练信号／边界列，最后把该列概括为“论文实验结论”。但[现有笔记](../../wiki/papers/2026-s2vopd.md)明确把可恢复性解释列为个人假说；只在另一列加待验证说明不足以约束整张表。

**修复要求：**

- 纠正 Reward Refresh 的更新对象。
- 把比较中的实验结果与解释假说拆开，各自标注来源和状态。
- 检查全部新写的 18 条索引片段和比较单元格，避免摘要新增原文没有的因果关系。

**验收：** 每个新增机制陈述都有真源依据；“教师缓存／学生刷新”一致；可恢复性解释在出现处标明待验证。

### R2 · P1：全文搜索和段落直达没有实际完成

**位置：** [wiki-index.js](../../site/assets/wiki-index.js)；[wiki-slides.js](../../site/assets/wiki-slides.js) 第 334～341、382～387、415～418 行。

当前九篇 `searchable` 合计只有 1089 个字符，另有 18 条手写摘要片段。正文没有被完整索引，匹配用的 corpus 甚至不包含 `snippets` 本身。

实测：

| 查询 | 结果 | 对照 |
|---|---|---|
| `y+` | U-OPSD、S²VOPD | 部分有效 |
| `attention sink` | GenLIP | 部分有效 |
| `流式 掩码` | VST | 部分有效 |
| `13.3` | 无结果 | U-OPSD 正文与卡壳点都有 |
| `Thinkless` | 无结果 | U-OPSD 的关联中明确出现 |
| `纯架构图` | 无结果 | LocateAnything 卡壳点明确出现 |

匹配到论文但摘要片段不含查询词时，`chooseSnippet()` 会回退到第一条，再显示“命中”，这不是实际的命中上下文。

问答没有独立 ID。搜 `y+` 后打开 S²VOPD，会到整个 `#pitfalls`，默认展开的是“训练看糊图为什么变强”；真正的 y+ 问答仍折叠。搜索结果没有完成“直接回到当时解释”的任务。

`site/notes/` 与完整笔记阅读模板也没有创建，“打开完整笔记”仍指向原始 `.md`。本地文件存在，线上可达性未验证；不能宣布 spec 的完整阅读出口已实现。

**修复要求：**

- 按 Markdown 的章节、问答和关系说明建立完整索引，去重后保存实际文本。
- 为问答提供稳定 ID，搜索直达对应内容并展开。
- 用实际匹配段落生成片段；未命中片段时不能冒充“命中”。
- 实现 spec 约定的完整笔记静态阅读页，让速览未收录的内容也有真实落点。

**验收：** 上述缺失查询可命中；每个结果进入实际匹配段落；S²VOPD 的 y+ 问题直接可读。

### R3 · P1：回忆模式中“查看解答”无法显示答案

**位置：** [wiki-slides.css](../../site/assets/wiki-slides.css) 第 1109～1111 行；[wiki-slides.js](../../site/assets/wiki-slides.js) 第 160～171 行。

复现步骤：

1. 打开 U-OPSD，进入卡壳点。
2. 点击“进入回忆模式”。
3. 点击第二题“查看解答”。

实际结果：按钮变成“收起解答”，`aria-expanded=true`，但答案仍是 `display:none`。原因是 `.reader-recall .qa.is-open .qa-a` 被 `!important` 强制隐藏。

顶部“先回忆”也只是 `#pitfalls` 链接，没有进入模式的事件绑定。进入模式后本质句、机制和关系仍可见，未实现 spec 的“初始只显示标题”。

**修复要求：**

- 使用明确的“只见标题 → 显示问题 → 展开所选答案”状态。
- 让每题展开动作优先于初始隐藏状态，保持按钮状态与视觉状态一致。
- 首页或顶部提供真正进入回忆状态的入口；已有正文阅读后的练习与正式复测继续区分。

**验收：** 首次进入只见标题；显示问题后能够逐题展开和收起；退出后恢复阅读；不自动写复测结果。

### R4 · P2：标签词表尚未接入，点击部分标签会漏掉自己

**位置：** [wiki-slides.js](../../site/assets/wiki-slides.js) 第 249～254、384 行；[wiki-index.js](../../site/assets/wiki-index.js) 第 11、96、130 行。

标签筛选仍按显示文字精确匹配 `page.tags`，没有按受控 ID 和别名归一。

- VideoChat3 页面标签为“全开源 4B”，索引保存“全开源”；点击页面上的标签得到 **0 篇**，连当前文章都消失。
- 选择“自蒸馏”只出现 U-OPSD，S²VOPD 未纳入该标签。
- `taxonomy.md` 虽已创建，但机制／目标维度和别名没有进入实际筛选模型，九篇 Markdown 均未增加 spec 中的结构化字段。

**修复要求：** 以词表稳定 ID 维护页面归属，显示名和别名映射到同一 ID；让页面标签与索引来自同一份元数据。

**验收：** 点击任何文章标签至少包含该文章；同义词得到相同结果；自蒸馏专题包含 U-OPSD 与 S²VOPD。

### R5 · P2：到期复测依赖写死的“今天”，不会随日期推进

**位置：** [wiki-slides.js](../../site/assets/wiki-slides.js) 第 385 行；[wiki-index.js](../../site/assets/wiki-index.js) 第 120、137、154 行。

`review=due` 通过 `page.review.indexOf("今天")` 判断到期。LocateAnything 永久携带“今天复测”，Open-MOPD 和 S²VOPD 到 09-14 也不会因为日期到达而出现在到期列表中，除非人工修改显示文字。

另外，S²VOPD 网页问答仍写“两连犯，下次复测优先扫”，而旁栏显示已通过。历史提示没有日期语境，当前状态与历史卡壳仍然混在一起。

**修复要求：** 从 `review.md` 投影结构化日期和最近结果，按 Asia/Shanghai 比较 `nextReview <= today`；历史问题保留当时日期，不冒充当前弱项。

**验收：** 对 09-07、09-14、10-07 的日期边界做有意义的测试；无记录不视为过期；历史与当前标签不冲突。

### R6 · P2：维护规则和章节定位仍依赖旧的七页结构

**位置：** [wiki-slides.js](../../site/assets/wiki-slides.js) 第 80～93 行；[CLAUDE.md](../../CLAUDE.md) 第 71、102 行；[ingest 指令](../../.zcode/commands/ingest.md) 第 23 行。

JS 根据 section 数组位置分配语义 ID：第四节永远是 `mechanism-2`，第六节永远是 `pitfalls`。模板却明确允许删掉第二个机制，实际模板只有六个 section。按模板生成六节内容时，“卡壳点”会被赋予 `evidence`，“关联与来源”会被赋予 `pitfalls`，回忆增强找不到正确问答。

现行 schema 和 ingest 指令仍要求五至八张 slide、首页原分组登记、前后篇接环；没有静态索引、完整阅读页和新元数据的同步要求。新的首页又完全根据 `WIKI_INDEX` 渲染，按旧流程只登记 HTML 条目不能保证新文章被发现。

**修复要求：**

- 在模板与页面中显式声明语义 section ID，旧 slide ID 仅作为兼容锚点。
- 同步真实 schema 文件 `CLAUDE.md`，保留 `AGENTS.md` 符号链接。
- 更新 ingest/review 的索引、关系、完整笔记和复测状态同步步骤。

**验收：** 六节、七节、八节内容的问答定位均正确；新增一篇页面后能按维护流程进入列表与搜索。

### R7 · P2：排版仍保留旧封面与长段关系，阅读重点没有充分重组

**位置：** [wiki-slides.js](../../site/assets/wiki-slides.js) 第 112～113 行；[wiki-slides.css](../../site/assets/wiki-slides.css) 第 885～891、1488～1495 行。

九篇原有 HTML 正文没有重写，论文页改动主要是资源版本及新增索引脚本。关联旁栏直接复制整个旧“关联与来源”区，包含长说明、未来钩子和源文件信息，未提炼为两三条易扫读的关系。

实际观察：

- U-OPSD 桌面旁栏高度 763px，内容 887px，形成独立滚动区，与 spec 的单一主滚动要求不同。
- 390px 下，顶部目录高约 174px，核心直觉从 y≈298px 开始，第一屏仍被旧标题、长本质句和机构信息占满。
- 关键机制起点约 y=1711px，复制后的关系旁栏约 y=6137px；原文末尾的关联仍在，手机出现重复信息。
- 原有全行高亮、大号数字和“关键数字”优先结构仍在，缺少新方案的单一核心提醒与靠前边界。

**修复要求：** 压缩首页与文章封面；手机目录默认紧凑可展开；关系提炼后显示而非全文克隆；正文按机制／边界／个人易错点重新排优先级；避免侧栏独立滚动。

**验收：** 首屏出现清晰的核心提醒及机制入口；无需滚到文末才能访问重点关联；手机不重复展示两份长关系列表。

### R8 · P2：比较弹窗的小屏与键盘行为未完成

**位置：** [wiki-slides.css](../../site/assets/wiki-slides.css) 第 1556～1557 行；[wiki-slides.js](../../site/assets/wiki-slides.js) 第 184～233 行。

- 390px 下，面板可视宽度约 348px，内部表格强制 650px；必须横向滚动，未按 spec 逐维度重排。
- 打开后按 Tab，焦点离开弹窗；背景未设 inert，没有焦点循环，关闭后也没有明确恢复触发点。
- 弹窗没有回到各比较值依据段落的链接。
- 正文中普通跨篇链接被拦截成比较弹窗，和旁栏同名链接的行为不同，用户不容易预测点击结果。

**修复要求：** 窄屏按维度显示两篇；采用原生 dialog 或完整管理背景与焦点；恢复触发点；普通论文链接保持导航，比较使用明确按钮；加上依据链接。

**验收：** 键盘始终能在弹窗完成操作并退出；手机无需横向寻找第二篇；用户能回到比较条目的来源。

### R9 · P2：页面“返回知识库”丢失筛选来源

**位置：** [wiki-slides.js](../../site/assets/wiki-slides.js) 第 56～62 行。

首页有查询状态，但文章顶部固定链接为 `../index.html`，没有携带来源参数。通过筛选进入文章后，点这个返回入口会清空筛选。浏览器自身后退有机会恢复状态，但两种返回操作不一致。

**修复要求：** 进入文章时保留来源查询信息，返回入口优先使用有效来源；直接打开文章时回到默认首页。

**验收：** 搜索和标签组合后进入文章，点击页面返回入口仍回到原查询结果。

## 5. 建议返工顺序

1. **先修 R1、R3。** 纠正知识内容，修复回忆模式中明确失效的操作。
2. **随后完成 R2、R4、R5、R6。** 让内容真源、结构化元数据、完整索引、稳定锚点和维护流程一致。
3. **最后修 R7、R8、R9。** 收紧阅读密度，改善关系与比较交互，补齐返回行为。
4. 用 U-OPSD、S²VOPD 复验主要流程，再用 VST 长问答、Open-MOPD 宽表、LocateAnything 解码示意检查其他内容类型。

无需推翻已完成的自然滚动和专题入口，也不需要引入新框架。重点是完成内容与状态的数据结构，并让可见按钮真正完成它承诺的动作。
