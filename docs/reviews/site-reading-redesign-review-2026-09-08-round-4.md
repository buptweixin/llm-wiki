### T2-a：短语跨越加粗标签时，定位器找不到完整文本

**真实路径，两种通道均复现：**

1. 将视口设为 390×844，打开首页，在搜索框输入 `关键在梯度路由方式`。
2. 在 GenLIP 结果中点击第二条 **“命中 全文 · 关键机制”**，不要点击上面的速览片段。
3. 进入 `notes/papers/2026-genlip.html?from=…#mechanism`。
4. 页面停在“关键机制”的 Prefix-LM 开头。要找的短语位于视口 **y≈912～930px**，844px 屏幕内不可见，仍需继续滚动。

首页的全文片段确实包含该短语，完整笔记也保留了它，因此不是索引漏词。真源为 [GenLIP Markdown](../../wiki/papers/2026-genlip.md) 第 65 行：

```markdown
关键在**梯度路由方式**。
```

在 HTML 中，它被分成 `关键在` 和 `<strong>梯度路由方式</strong>` 两个文本节点。`locateHitText()` 在每个独立 Text 节点的 `nodeValue` 内查完整 token，没有任何单个节点包含全部九个字，最终走 `if (!found) return`，留下浏览器原生的整章锚点落点。

**修复标准：**

- 按用户看到的连续文本匹配，不能让 strong、em、code、a 等行内标签切断短语定位。可在合理段落的 `textContent` 上寻找命中，再定位对应段落或文本范围。
- 点击上面的全文片段后，完整短语及解释它的上下文直接出现在顶栏下方；保留正文的加粗和原文，不通过改写真源或专门补这个词规避问题。
- 至少再抽取一条跨其他行内标签的真实短语验证，避免只对 strong 或本例写特例。

### T2-b：多词查询在找到第一个常见词后就停止，错过真正的短语

**真实路径，两种通道均复现：**

1. 首页搜索 `token 自由双向交互`，其中是一个普通空格。
2. 点击 GenLIP 的 **“命中 全文 · 关键机制”**。
3. 页面定位到章节前部的 `[图像 token × M] + [文本 token × L]`，这里的 `token` 位于 y≈191～206px。
4. 查询中的完整短语实际在章节尾部“④ 推理：退化回标准 ViT”的段落，位于 **y≈1801～1818px**，还隔着两屏左右。1440×900 桌面复验时，该短语仍位于 **y≈1213～1231px**，不可见。

真源为 [GenLIP Markdown](../../wiki/papers/2026-genlip.md) 第 79 行：“没有文本，所有视觉 token 自由双向交互”。

`tokensFor()` 将查询拆成 `token` 和 `自由双向交互`。新增循环先扫描整个章节找 `token`，找到第一个就设置 `found` 并停止，第二个词不再参与落点选择。虽然 `matchingEntries()` 要求条目包含全部查询词，落点选择却只满足任意一个词。首页片段也沿用首词截取，会显示前部的通用 token 内容，用户仍得自行找更具体的限定词。

**修复标准：**

- 当完整查询短语在正文中存在时，优先定位该短语所在的最小合理上下文；不能因前面出现通用词就提前停止。
- 保留空格分词搜索能力。非连续的多词查询也应优先选择覆盖查询词的上下文；只有无法找到这样的局部上下文时才降级。
- 本例必须直接显示包含 `token 自由双向交互` 的推理段落，而不是只显示第一个 `token`。片段与落点使用一致的匹配选择，避免给出互不相干的阅读提示。
- 继续保留 `from` 中的原始查询与筛选值；匹配归一化不能改坏返回状态。
