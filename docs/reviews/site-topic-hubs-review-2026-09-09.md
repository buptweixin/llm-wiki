## 2. R1 / P2：蒸馏本质句把特定自蒸馏条件扩展成 OPD 通则

位置：[蒸馏真源第22行](../../wiki/syntheses/distillation.md#专题本质)，同时影响首屏本质句、takeaway、完整笔记与索引。

当前说法是“教师必须比学生多知道点什么，否则师生分布相同、KL 恒为 0”。依据中的 [U-OPSD 关键机制](../../wiki/papers/2026-u-opsd.md#关键机制) 第62行讨论的是该自蒸馏构造里，让学生也看到 y+ 后教师与学生相同的情形。

这里漏掉了同模型、同条件等限制。教师和学生看到相同输入，并不能推出两个不同模型的输出分布相同；同样，存在分布差异也不自动表示教学信号有用。把这一条件命题放大到整个 OPD 家族，会让专题里不同专家教师的 Open-MOPD 也被误读成必须靠额外输入制造差异。

修复建议：本质句直接概括三篇的分工，如“前两篇构造自蒸馏中的师生信息差，第三篇解决多教师训练预算分配”；KL 为零的解释限制在师生分布确实相同的设置下。若要提出更一般的理论解释，需另行讨论并保留条件。

验收：真源、导读、完整笔记和搜索摘要同时更正；本质句不再把 U-OPSD 的局部条件作为 OPD 普适必要条件。

## 3. R2 / P2：组合设想仍被归入“库内对照”

位置：[蒸馏关系记录](../../wiki/syntheses/distillation.md#关系记录) 的 `rel-distill-orthogonal-slices`、`rel-distill-self-asymmetry-in-multi`；[视频关系记录](../../wiki/syntheses/video-understanding.md#关系记录) 的 `rel-video-combination-timing-conflict`。

最直接的例子是蒸馏第72行：文字明确写“这是组合设想，库内无实验”，证据状态却是 `synthesis`，网页显示“库内对照”。第70行把“两个研究问题正交”与“组合方案成立”合在一个状态下。视频页也将组合可行性和调度冲突判断混在同一记录中。

这不等于所有跨篇推理都要实验才能写。问题在于本轮方案已经明确区分：基于现有材料的对照与尚未验证的组合主张应分开。用户理解了一种设想，也不会使它自动成为已验证关系。

修复建议：保留“信号来源与预算分配是不同问题”等直接对照为 `synthesis`；把组合可行性、组合后的收益或具体行为拆成独立记录并标 `hypothesis`。图注、正文、关系卡与搜索片段都保留就地限定，避免只在页尾统一声明。

验收：查看上述关系时，读者能分别辨认已知事实、库内对照和待验证组合；不能同时读到“组合成立”和只有“库内对照”的标签。

## 4. R3 / P2：依据指纹只看 HTML，Markdown 真源变化时仍全绿

位置：[生成器](../../scripts/build-wiki-index.mjs) 第318～326行的 `anchorText()`、`evidenceFingerprint()`；[静态检查](../../scripts/check-site.mjs) 对依据指纹的核对逻辑。

本轮在临时副本做了以下实验，没有改真实知识页：

1. 仅在 `wiki/papers/2026-s2vopd.md` 的 `## 关联` 下新增“来源依据已更新：旧组合主张撤回，等待重新验证。”。
2. 保持所有 HTML 与关系记录的旧指纹不变。
3. 运行索引生成器，退出码 **0**。
4. 运行 `check-site.mjs`，退出码 **0**，仍显示“全部通过”。

原因：指纹取完整笔记 HTML 的可见文字，未核对对应 Markdown 依据段落。现有失败样本覆盖的是修改派生 HTML，因此不能证明真源变化会被识别。实际后果是原笔记已修正，专题仍表达旧结论，检查却给出成功信号。

修复建议：为每条依据建立 Markdown 段落的稳定映射，指纹绑定真源内容；同时校验完整笔记对应段落是否过期。若采用整页真源指纹作为第一步也可以，但应说明它会触发更宽范围的人工复核。拒绝生成时保持旧索引字节不变。

验收：加入“只改 Markdown、HTML 不变”的持久反例；新旧依据不一致时必须失败，并指出专题、关系 ID、真源位置。同步并复核后才恢复通过。

## 5. R4 / P2：规范关系更新后，网页和论文卡片没有跟随或报错

位置：[生成器](../../scripts/build-wiki-index.mjs) 第436行继续从旧索引保留 `relations`；[检查器](../../scripts/check-site.mjs) 第288～289行仅验证导读关系块 ID 存在。

第二个独立临时副本实验：

1. 只将蒸馏 Markdown 中 `rel-distill-self-asymmetry-in-multi` 的状态从 `synthesis` 改为 `hypothesis`。
2. 运行生成器，退出码 **0**，索引 `records` 按真源更新。
3. 导读页同 ID 的关系块仍显示旧的 `evidence is-synthesis` 和“库内对照”；完整专题笔记也未同步。
4. 再跑检查器，退出码 **0**，仍显示“全部通过”。

另外，论文关系卡消费的是保留的 `page.relations`，并未通过规范关系 ID 从 `records` 推导。因此“关系表是规范记录”的约定目前没有贯穿到阅读入口。

修复建议：让适用的论文关系卡引用规范关系 ID；从一份记录生成方向适当的卡片和关系说明。对静态导读与完整笔记，至少独立核对关系类型、主张和证据状态，而不只检查 ID。反向展示不得改变前置方向或证据强度。

验收：更改一条关系状态或主张后，相关投影必须同步或检查失败；新增上述状态变更反例。不要依赖生成器与检查器对同一个过期 HTML 自我对账。

## 6. R5 / P2：改写后的复述被标成用户原话

位置：[视频专题真源](../../wiki/syntheses/video-understanding.md#跨篇卡壳点) 第112行、[视频导读](../../site/topics/video-understanding.html#qa-video-compress-vs-memory) 第269行，以及完整专题笔记和全文索引。

专题使用“用户当时的原话”引出了一段压缩改写。对照 [VST 原笔记](../../wiki/papers/2026-vst.md#我的复述) 第103行：

> VST 用文本记录流式输入的前序所有片段+前序少数视频帧信息汇总合成回答，而 VideoChat 通过压缩视频帧的token数记更多上下文。两者可以同时进行。

专题把它改成“VST 用文本记录流式输入的前序片段信息汇总回答，VideoChat 通过压缩视频帧 token 记更多上下文，两者可以同时进行。”，省略了“前序少数视频帧”等细节，却仍称原话。

修复建议：逐字引用并链接来源，或明确写“对当时复述的概括”。历史复述保留当时的表达和不精确之处，LLM 的补充解释另起一段。

验收：带“原话”的文字可逐字回查；网页、完整笔记和索引同步，避免改写真源原话去迎合派生文本。

## 7. 非阻断的阅读体验建议

- **手机关系图还可以更易读。** 390px 视口下，图固定最小宽度640px，需要横滑才能同时看到两个问题分支；桌面1280px下正文图中的小字也偏小。横滑没有破坏整页布局，符合允许的降级方式，因此本轮作为 P3 优化。优先采用手机纵向分支图、缩短节点副标题并增大字号，保留完整文字关系表。
- **依据页缺少直接返回专题的入口。** 从专题比较表进入 U-OPSD 完整笔记后，当前页没有指向专题的链接；浏览器后退有效，回首页也能保留筛选，但“核对完依据继续比较”还需要依赖后退。可传递有限专题 ID/锚点，在完整笔记提供“返回专题比较”，保留独立的首页来源状态。
- **首屏仍可压缩。** 蒸馏封面的长本质段与紧接着的 takeaway 重复较多，关系图要再往下读。缩短成一句主题判断，让问题地图更早出现，会更符合“快速理清关系”的目标。
