## 2. S2-a · P2：SOURCE 区的完整笔记出口没有继承来源

**位置**：[wiki-slides.js](../../site/assets/wiki-slides.js) 第 721～726 行；示例链接在 [U-OPSD 速览页](../../site/papers/2026-u-opsd.html) 第 205 行。

### 最短复现

file:// 与本地 HTTP 均执行，无需模拟日期：

1. 打开首页 `index.html?q=y%2B&topic=distillation&tag=self-distillation`。
2. 点击 U-OPSD 标题进入速览。
3. 滚到文末“关联与来源”，在 SOURCE 区点击 `notes/papers/2026-u-opsd.html` 这条完整笔记链接。
4. 在完整笔记页点击顶部“知识库”。

实际：第 3 步地址已变为无查询参数的 `notes/papers/2026-u-opsd.html`；第 4 步返回裸 `index.html`，搜索框清空，恢复全部九篇。预期：仍保留 `q=y+ / topic=distillation / tag=self-distillation`。

### 两跳与四字段复现

在首页使用 `q=y+ / topic=distillation / tag=self-distillation / review=due`，进入 U-OPSD → 侧栏 S²VOPD → 侧栏 Open-MOPD → **SOURCE 区完整笔记** → 知识库。

| 阶段 | 实际来源 |
|---|---|
| U-OPSD、S²VOPD、Open-MOPD 速览 | 四字段正确；每页一个 from，解码后长度均为 58，无嵌套增长 |
| Open-MOPD SOURCE → 完整笔记 | from 消失，四字段全空 |
| 完整笔记 → 首页 | 无筛选，显示全部九篇 |

两通道一致。四字段用例在起点注入上海 2026-10-07 的浏览器 Date，使 due 有结果；最短复现已证明此缺陷与日期无关。

原因：静态链接补参只匹配同目录 `文件名.html`，不匹配 `../notes/papers/文件名.html`。侧栏 `.context-action` 与手机 `.mobile-cover-link` 使用 `withFrom()`，SOURCE 中的静态完整笔记链接没有经过同样处理。不能用另两个出口通过来代表全部完整笔记出口通过。

### 修复标准

1. 让九篇速览 SOURCE 中的完整笔记链接继承同一份规范化 from；可以显式处理此类站内出口，不需要修改外部来源或源文件链接。
2. 最短路径和两跳路径都恢复原 `q/topic/tag/review`，返回原结果；有 hash 时保留 hash，from 只出现一次，多跳不增长。
3. 无来源直接访问仍不添加空参数；标签点击继续作为新筛选操作。
4. 双通道复验手机入口、侧栏入口和 SOURCE 入口；将“不同完整笔记出口具有相同来源行为”加入可重复检查。

## 3. S4-a · P2：重建时静默丢弃缺少锚点的完整章节

**位置**：[build-wiki-index.mjs](../../scripts/build-wiki-index.mjs) 第 175～196 行，尤其第 183～185 行；另见其旧全文条目移除及后续锚点校验流程。相关漏检在 [check-site.mjs](../../scripts/check-site.mjs) 的 C2、C10。

### 复现步骤与实际结果

1. 保持 GenLIP Markdown 不变。
2. 在 `site/notes/papers/2026-genlip.html` 中，仅把 `id="mechanism"` 改为 `id="r7-missing"`，保留章节正文。
3. 运行 `node scripts/check-site.mjs`：退出 1，能发现既有索引中的 `#mechanism` 已失效。
4. 运行 `node scripts/build-wiki-index.mjs`：**退出 0，无错误，写入索引，条目从 224 减少为 223**。
5. 再运行 `node scripts/check-site.mjs`：**退出 0，输出“全部通过”**。

这不只是报错文案不足：重建把本应暴露的派生文件损坏转化为静默搜索缺失。连续两次生成仍一致，因此幂等和“干跑逐字一致”不能单独证明索引完整。

原因：`projectedEntries()` 只在 `renderedSections[section.id]` 存在时添加条目，否则直接跳过。旧全文条目先被过滤掉，随后锚点校验只检查留下的新条目，已消失的章节没有机会报错。C2 同样只检查当前索引中的条目，C10 则与同一套有缺口的生成器对账。

### 修复标准

1. 对已识别、非空且应投影的真源章节，建立“必须存在”的章节／锚点集合；缺失或改名时报告页面、真源章节与预期锚点，不能直接省略。
2. 此反例必须非零退出，并保持原索引文件字节不变。缺失完整笔记文件、未知标签等现有拒绝生成行为继续保留。
3. 静态检查应独立比较真源预期章节与实际派生／索引覆盖，避免先丢条目再因自我对账而通过。
4. 将上述“只改一个完整笔记 id”反例加入持久回归集；恢复锚点后重新生成应恢复 224 条及 `Dataset-S2`，连续两次一致。
5. 保留本轮已验证的专题、别名、标签、词表和复测字段传播，以及新增页面发现能力。
