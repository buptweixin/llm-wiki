# 知识库站点阅读体验改造 Spec

日期：2026-09-07  
状态：实施提案；本次仅编写文档，尚未改造或部署站点。  
适用范围：`site/` 及其依赖的知识元数据、模板和维护流程。  
定位：工程与产品维护文档，不属于通过费曼检验入库的知识页。

## 1. 目标与设计判断

将站点从整屏纵向幻灯片，改成支持快速定位、连续阅读和跨篇比较的知识阅读站。

主要使用场景假设：用户隔一段时间回到已经学过的内容，需要找回某个机制或困惑，重建直觉，再沿相关问题继续阅读。桌面端承担较长阅读与对比，手机端承担快速回查；两端都必须可用。

保留现有暖灰底色、细线、单一朱砂强调色与明暗主题。改造重点是滚动行为、信息层级、查找入口和关系解释。

### 1.1 成功标准

- 可以自然滚动到任意段落；长内容不会被方向键或自动吸附跳过。
- 不必记得论文名称，也能通过主题、机制或曾经卡壳的问题找回知识。
- 进入一篇文章后，能迅速辨认核心机制、关键边界和最易混淆之处。
- 相关链接说明为什么值得读、应比较什么，并可直达有关段落。
- 历史卡壳、当前复测状态、尚未解决的问题分别呈现。
- Markdown 继续作为内容真源；网页保持静态、可离线使用。

### 1.2 第一版范围

1. 自然滚动阅读页、语义目录和稳定段落链接。
2. 问题专题首页、紧凑论文列表、可点击标签。
3. 覆盖标题、正文、别名、卡壳问题和关系说明的本地搜索。
4. 有解释的关联卡、反向引用和两篇文章的轻量比较。
5. 历史卡壳展示、主动回忆入口和来自 Markdown 的复测状态。
6. 完整笔记的可读出口、本地与线上路径验证。
7. 九篇现有论文、共享模板、索引与维护规则迁移。

### 1.3 后续可选项

- 全库可拖拽知识图谱、复杂概念树和阅读路径编辑器。
- 向量搜索、自然语言问答、浏览器内 LLM 调用。
- 在线编辑、自动评分、跨设备练习记录同步。
- 独立 PPT 展示模式、用户自定义排版系统。
- 大面积学习统计、连续打卡和游戏化功能。

第一版不依赖这些功能。当前九篇内容适合轻量静态实现。

## 2. 现状与问题证据

以下为 2026-09-07 的本地代码审查及浏览器观察。观察环境不代表所有浏览器均已验证。

| 问题 | 已确认的实现或内容 | 影响 |
|---|---|---|
| 强制分页 | `.deck` 使用 `scroll-snap-type: y mandatory`；`.slide` 至少一屏高、`scroll-snap-stop: always`、内容垂直居中 | 短内容空白过多，相邻知识点难连续扫读 |
| 键盘跳过长内容 | 全局拦截方向键、空格、PageUp/Down，直接切换整个 section | 在 390 × 844 视口，U-OPSD 卡壳节约 1281px，可视区约 792px；一次 ArrowDown 直接离开该节 |
| 导航职责混淆 | 模板按钮是“上一张／下一张”，真实页是“上一篇／下一篇”；共享 JS 仍绑定本篇切节 | 文章跳转与章节跳转混用同一套行为 |
| 缺少语义目录 | 当前主要定位信息为 `1 / 7` 和 `slide-N` | 无法直接表达或跳到“机制”“边界”“卡壳点” |
| 重点位置靠后 | 九篇均为七节，卡壳点在第六节，正文关联集中第七节 | 个人理解资产与跨篇连接不易发现 |
| 强调失去选择性 | U-OPSD 部分表格每行都高亮；大号性能数字比问答更突出 | 用户难判断究竟应该记住什么 |
| 标签不可操作 | 九篇共 43 个标签均为文字 span | 无法通过标签查找同类内容 |
| 搜索范围有限 | 首页仅对条目 `textContent` 做子串匹配 | 正文术语、卡壳问题和多数关系说明无法命中 |
| 首页分类无区分度 | 只有论文类有内容，概念、代码、综合为空 | 用户仍需记住论文名才能定位 |
| 状态可能过时 | S²VOPD 网页保留 y+“两连犯、下次优先扫”，而最新复测已通过 | 历史问题容易被误读为当前弱项 |
| 证据层级容易丢失 | “信息可恢复性解释散度选择”在 Markdown 中明确为个人假说 | 普通关系连线容易把推演呈现为论文定论 |

## 3. 用户任务与优先级

| 编号 | 用户任务 | 目标路径 |
|---|---|---|
| J1 | 忘了 y+ 是什么，找回当时的解释 | 搜索“y+／完整轨迹” → 命中问答 → 段落 |
| J2 | 快速重建一篇论文的直觉 | 首页或搜索 → 一句话本质 → 机制与边界 |
| J3 | 比较两篇蒸馏方法 | 文章关联 → 比较信息差、训练信号、散度和适用条件 |
| J4 | 不记得论文名，只记得研究方向 | 专题或标签 → 论文列表 → 阅读 |
| J5 | 先凭记忆复述，再看自己曾经卡住的点 | 回忆入口 → 只见标题 → 自主展开问题及解答 |
| J6 | 手机临时查一个机制或数值 | 搜索／目录直达 → 阅读局部内容 → 返回原筛选状态 |

优先顺序：J1、J2、J4 → J3、J6 → J5 的便利性增强。正式费曼复测流程继续由用户与 LLM 完成。

## 4. 信息架构与导航

### 4.1 首页顺序

1. 站点名和全站搜索。
2. 四个问题专题入口。
3. 当前筛选条件、结果数量、论文列表。
4. 一条克制的复测提示：到期数量与入口；无到期内容时省略。

首页不展示空的概念、代码、综合分组。后续这些类型实际有内容时，作为筛选维度接入同一列表。

默认顺序继续采用 `index.md`，降低迁移成本；有搜索词时按相关性排序，同分再用索引顺序。第一版不增加多个排序菜单。

### 4.2 初始专题

| 稳定 ID | 可见名称 | 现有页面 | 专题问题 |
|---|---|---|---|
| `video-understanding` | 视频理解与响应 | VideoChat3、VST、Video-o3 | 如何压缩感知成本、安排思考时机、主动寻找证据？ |
| `visual-encoders` | 视觉编码器 | GenLIP、LaSt-ViT | 预训练目标如何影响表示，模型为什么走注意力捷径？ |
| `distillation` | 蒸馏与训练预算 | U-OPSD、S²VOPD、Open-MOPD | 教师信号从哪里来，师生差异如何构造，预算如何分配？ |
| `structured-output` | 结构化输出与定位 | LocateAnything | 解码单位改变后，定位精度与输出速度如何变化？ |

每篇先设置一个主专题，跨专题联系通过机制标签与关系表达。专题只是已有知识的聚合入口，不自动生成未经费曼检验的新结论。

### 4.3 列表项

每项只展示：论文简称、精简本质描述、两至三个标签、必要时一条复测状态。搜索状态下增加命中片段，取代重复的长摘要。

整项主标题进入文章；标签独立可点击，HTML 中不能把按钮嵌进整项大链接。日期和机构降为次要元信息，首页不展示机构长列表。

### 4.4 URL 与返回行为

- 保留现有 `site/papers/<slug>.html` 路径。
- 新章节使用可读且稳定的 ID，如 `essence`、`mechanism`、`evidence`、`pitfalls`、`relations`、`sources`。
- 被引用的问答使用独立 ID，如 `qa-y-plus`，避免依赖问题全文生成易变锚点。
- 旧 `#slide-1` 等链接保留兼容锚点，逐页映射到对应的新章节。
- 首页状态写入 URL，例如 `index.html?q=轨迹&topic=distillation&mechanism=self-distillation`。
- 输入搜索词时用替换历史状态，避免每个字符产生一个后退步骤；明确切换筛选时可新增历史状态。
- 浏览器后退恢复筛选与正常滚动位置；“返回知识库”链接保留已知的来源筛选。
- 查询参数缺失或未知时回到有效默认状态，不阻塞页面正文。

## 5. 单篇阅读页

### 5.1 布局

```text
顶部：返回知识库 / 文章名 / 搜索入口

桌面：本文目录        正文                          为什么值得一起读
      核心直觉        标题、主题、短摘要              关系类型与理由
      关键机制        这篇最值得记住                 两篇比较入口
      证据与边界      机制、例子、证据                当前复测记录
      曾经卡壳        历史问答
      关联与来源      来源与完整笔记

手机：顶部 → 可展开目录 → 正文 → 关联与来源
```

- 使用浏览器文档作为主要滚动容器；正文和侧栏不各自建立滚动区。
- 大桌面允许目录与关联旁栏 sticky；旁栏高于可用视口时随文档正常滚动。
- 中等宽度先收起左目录为顶部目录；窄屏全部变为单栏。
- 首屏提供关联数量或相关论文入口，手机用户不必滑到文末才知道存在关联。
- 顶部不再提供混淆章节和文章含义的前后按钮。

### 5.2 内容顺序与显示规则

| 模块 | 默认展示 | 约束 |
|---|---|---|
| 标题区 | 简称、一句话本质、少量可点击标签 | 不使用独占一屏的封面；机构、DOI 等放来源区 |
| 核心提醒 | 一条最值得记住的判断 | 可以是机制、代价或容易混淆的区别，不固定为性能数字 |
| 关键机制 | 简短解释与适合该内容的示意 | 基本理解链默认展开；不得把每一段都折叠 |
| 证据与边界 | 关键实验及成立条件 | 数值必须带模型、任务、比较对象或必要口径 |
| 曾经卡壳 | 具体问题、历史状态、精选解答 | 不把历史错误直接转成当前“未掌握”状态 |
| 关联与来源 | 完整关系列表、原文与完整笔记出口 | 首屏另有紧凑入口，文末提供完整说明 |

不再限制每篇恰好五至八节。完整机制决定章节长度；短内容不被拉长，长内容不为凑页数而过度压缩。

### 5.3 重点与渐进展开

- 全文最高视觉强调只给一个核心提醒；其他章节以标题、排版和少量加粗建立层级。
- 每个章节至多一条局部重点提示，避免整表或每一行同时着色。
- 基本机制与关键边界默认可读。
- 大型消融表、补充推导、历史复述可用原生 `details/summary` 展开。
- 直接访问折叠内容内的 hash 时，自动展开祖先 `details` 后定位。
- 浏览器查找和页面搜索都应尽量覆盖折叠内容；跨浏览器验证发现差异时，搜索直达必须自行保证展开。

### 5.4 视觉形式由内容决定

| 内容 | 优先表达 |
|---|---|
| U-OPSD / S²VOPD | 教师与学生输入差异的对照，明确额外信息是什么 |
| VST / Video-o3 | 视频时间线与推理发生时机，区分查询前后 |
| Open-MOPD | 训练预算如何被分配与浪费的因果链 |
| GenLIP / LaSt-ViT | 注意力或信息流向，配合具体 patch 例子 |
| LocateAnything | token 顺序与整框并行解码的逐步示例 |

第一版只制作帮助重建直觉的必要示意。已有笔记指出某种解释无效时，应采用后来讲通的具体例子；不能把所有论文套成同样的三张流程卡。

## 6. 标签与元数据

### 6.1 标签维度

| 维度 | 用途 | 示例 | 每篇建议数量 |
|---|---|---|---|
| 主题 `topic` | 定位研究问题 | 蒸馏与训练预算、视觉编码器 | 一个主专题 |
| 机制 `mechanisms` | 找采用相近方法的知识 | on-policy 蒸馏、自蒸馏、文本记忆、块解码 | 一至三个 |
| 目标 `goals` | 找解决相近问题的方法 | 减少外部监督、降低响应延迟、提高定位精度 | 一至两个 |

技术标签与学习状态分开。不能把“待复习”“已通过”加入机制标签。

新增 `taxonomy.md` 作为受控词表，记录维度、稳定 ID、显示名称、别名和一句适用定义。新增标签须有实际查找用途，避免按论文里的每个术语造标签。

例如：`on-policy-distillation` 的别名包括 `OPD`、`on-policy 蒸馏`；`self-distillation` 仍是独立机制，不能因为都带“蒸馏”就合并。

### 6.2 推荐的最小页面字段

在 Markdown 页头增加结构化元数据；现有标题、正文和 Zotero 三件套继续保留。以下是目标格式示意，实施时再填充页面：

```yaml
---
id: 2026-u-opsd
type: paper
aliases: [U-OPSD, On-Policy Self-Distillation without Any Supervision]
topic: distillation
mechanisms: [on-policy-distillation, self-distillation]
goals: [reduce-external-supervision]
updated: 2026-09-07
---
```

- `id` 与文件名对应，跨网页、搜索与复测数据使用同一个 ID。
- 一句话本质沿用正文中的已有字段，不再额外维护一个含义不同的首页摘要真源。
- 网页短摘要可以从本质句提炼，但必须保持机制、范围和证据含义。
- 作者、DOI、itemKey 沿用论文表头，不为了前端再重复维护一套。
- 复测日期和结果来自 `review.md`；未解决问题来自 `questions.md`。

## 7. 关系模型与比较

### 7.1 关系必须有理由

第一版每篇重点展示两至三条关系。不得只按共享标签自动宣布两篇有实质机制关联。

关系至少包含：来源页、目标页、关系类型、一句原因、依据段落、证据状态；可选目标段落锚点。

推荐类型：`compare`（对比）、`complement`（互补）、`prerequisite`（理解前置）、`possible-combination`（可能组合）、`tension`（结果或解释存在差异）。

“有链接”和“有科学结论”不是同一件事。反向引用可以从已有链接自动汇总，但不能自动把“前置”反转为“前置”，也不能把“可能组合”变成“已验证组合”。

### 7.2 证据状态独立于关系类型

| 状态 | 含义 | 展示要求 |
|---|---|---|
| `reported` | 笔记中有来源支持的实验或作者结论 | 显示适用条件并链接依据 |
| `synthesis` | 基于已入库内容形成的对照或综合 | 标“库内综合”，保留各自来源 |
| `hypothesis` | 尚待实验或后续材料验证的解释、组合设想 | 明确显示“待验证”，不得使用已证实口吻 |

例如，U-OPSD 与 S²VOPD 的散度消融选择不同，可分别展示已有笔记记录的结果；“信息可恢复性解释这种差异”必须单列为假说。

### 7.3 真源存储形式

在 Markdown 的“关联”节用结构化表格记录关系，较长解释继续写在表格之后。示意：

```markdown
| 关系 | 目标 | 为什么一起读 | 证据状态 | 依据 |
|---|---|---|---|---|
| compare | [S²VOPD](2026-s2vopd.md) | 比较师生信息差的来源与散度选择 | synthesis | [本文机制](#mechanism)及目标页相关段落 |
```

每条关系的证据状态只约束该行具体表述。同一对页面包含实验对照与个人假说时，应拆成不同说明，不能用一个标签覆盖所有说法。

### 7.4 并排比较交互

- 从关系卡进入，第一版只支持两篇比较，不提供任意数量的列选择器。
- 共享维度按问题选择，例如“教师额外知道什么／学生输入／训练信号／实验选择／适用边界”。
- 宽屏并排，窄屏按同一维度先后展示两篇，方便逐项比较。
- 每个值可回到原笔记的依据段落；未记录的信息显示“笔记未记录”，不推测补齐。
- 实验条件不同的性能数值不排列成未经说明的优劣榜。
- 关闭比较后保留原文阅读位置。

第一版比较内容仅提炼已有材料。需要提出新解释时，作为待讨论内容处理，不能通过前端改造绕过费曼入库。

## 8. 搜索规格

### 8.1 索引范围

索引包含：简称、全称和别名；本质句；主题及标签别名；章节标题与正文；卡壳问题和解答；关系理由。

正文按章节或问答形成条目，每条保存 `pageId`、`heading`、`anchor`、`text` 和必要的目标路径。元数据与重复出现在速览／完整笔记中的内容只索引一次。

索引作为静态 `site/assets/wiki-index.js` 随页面加载，避免 `file://` 下用 fetch 读取 JSON 或 Markdown 导致浏览器限制。HTML 正文不依赖索引脚本成功执行。

### 8.2 匹配与排序

1. 去除两端空格，拉丁字符忽略大小写；按受控词表展开已知别名。
2. 单个词在标题、标签、章节和正文中进行子串匹配。
3. 空格分开的多个关键词采用 AND；同一维度的多个筛选值采用 OR，不同维度之间采用 AND。
4. 标题／简称精确匹配优先，其次别名与问题标题，再次本质句和正文。
5. 同一论文结果合并，默认展示最多两个相关段落；提供进入文章的入口。
6. 排名一致时按 `index.md` 顺序，保证结果稳定。

第一版不承诺任意自然语言问句都能语义匹配。查找依靠原文、问题标题和有意维护的别名，不引入模型或向量服务。

### 8.3 结果与空状态

- 显示论文名、命中章节、简短上下文和关键词强调。
- 点击命中片段直达实际存在的内容；若速览未收录该段，则进入完整笔记阅读页的对应段落。
- 查询为空时恢复当前标签筛选列表。
- 无匹配时展示当前条件及“清除筛选”操作，不给出未经来源支持的答案。
- 用户输入作为文本处理，不能直接拼进 HTML 或未经转义的正则表达式。
- 返回、刷新和复制 URL 后，查询词及筛选条件保持一致。

验收例子：搜索 `y+` 命中 U-OPSD 及 S²VOPD 的相关问答；`attention sink` 命中含该概念的笔记；`OPD` 能通过别名找到有关页面；`流式 掩码` 命中 VST 的对应内容。

## 9. 卡壳点与复测状态

### 9.1 三类信息分开

| 信息 | 真源 | 展示含义 |
|---|---|---|
| 历史卡壳 | 各笔记的“卡壳点与解答”和“我的复述” | 当时如何误解、后来如何讲通 |
| 当前复测记录 | `review.md` | 最近复测日期、结果、下次时间 |
| 尚未解决的漏洞 | `questions.md` 中未勾选条目 | 仍需补齐的理解问题 |

`questions.md` 为空时，不从历史卡壳数量推断当前存在未理解内容。页面级复测通过也不等于每个历史问题都有独立的通过记录；细到问题的状态只有在日志明确记录时才显示。

### 9.2 阅读与回忆行为

- 普通阅读中，问题标题始终可见；最相关的一题可默认展开，其余按需展开。
- 首页“先回忆”入口直接进入回忆状态，初始只展示论文标题，隐藏本质句、标签提示、答案和关系提示。
- 用户自己复述后，点击“查看检验问题”，再逐个展开解答。
- 从已经读过正文的页面切换回忆状态，仅作为练习；不声称满足一次独立复测条件。
- 点击展开、停留时长或勾选按钮都不会自动判定掌握，也不自动修改 `review.md`。
- 正式复测仍按知识库流程，由 LLM 核对用户复述并更新真源。

### 9.3 日期与状态

日期按 Asia/Shanghai 的日历日判断，到期条件为 `nextReview <= today`。缺失日期展示“暂无记录”，不默认为过期。

网页显示数据更新时间。新一次 review 完成后同步相应网页和静态索引；历史题目中的“下次优先扫”应标注当时日期，当前提示使用最新复测记录。

## 10. 视觉、交互与可访问性

### 10.1 阅读尺度

- 桌面正文初始目标宽度约 640～760px，实际按中文行长约 36～44 字校准。
- 正文初始目标 16～17px，行高 1.75～1.9；手机不通过缩小字体塞入宽表。
- 主要标题控制在阅读需要的尺度，不设置占据首屏的大字封面。
- 数值、代码和参数使用现有 mono 字体；解释性的中文单元格允许换行。
- 所有颜色、字号、间距与状态样式来自共享 CSS token；禁止页面私设样式。
- 保持浅色／深色主题；普通正文对比度至少 4.5:1，大字至少 3:1。

### 10.2 滚动与键盘

- 移除新阅读页的整屏高度、强制吸附和垂直居中。
- ArrowUp/Down、PageUp/Down、Space、Shift+Space、Home/End 使用浏览器原生行为。
- 不注册全局快捷键覆盖输入框、按钮或可展开控件。
- 目录为真实链接，章节有稳定 ID；sticky 顶栏通过 `scroll-margin-top` 避免遮住目标标题。
- 尊重 `prefers-reduced-motion`，不以入场动画隐藏正文。
- DOM 顺序遵循正文阅读顺序；标题级别、导航区域、正文和旁栏使用语义 HTML。
- Tab 焦点清晰可见，触屏主要控件的有效目标约 44px；关键操作不依赖 hover。

### 10.3 手机、表格和长内容

- 页面整体不产生横向滚动。
- 确有二维对照需要的宽表放在单独的横向滚动区域，提供可见提示；普通文字表优先换行或改为逐项对照。
- 长公式、代码和路径只允许在各自区域横向滚动。
- 320px～430px 宽度下，目录和标签换行；导航不挤掉论文标题。
- 浏览器放大到 200% 后，内容重新排布，控件不遮挡正文。

## 11. 静态实现与内容真源

### 11.1 推荐目录变化

以下为实施后的目标目录，当前 spec 编写不创建这些产品文件：

```text
taxonomy.md                         受控标签词表
wiki/papers/*.md                    内容与关系真源，增加最小元数据及稳定锚点
review.md / questions.md            学习状态真源
site/
  index.html                       专题、搜索与列表
  _template.html                   新阅读模板
  _note-template.html              完整笔记阅读模板
  papers/*.html                    保留原路径的速览阅读页
  notes/papers/*.html              完整 Markdown 的静态可读投影
  assets/
    wiki-slides.css                 沿用共享文件，增补阅读样式
    wiki-slides.js                  沿用共享文件，迁移导航交互
    wiki-index.js                  可再生成的搜索、标签、关系及复测投影
```

沿用共享资源文件名，避免单纯为改名增加迁移面。待旧滑页逻辑完全退出后，再删除本次迁移造成的无用规则。

### 11.2 零运行时服务与零构建框架

- 不引入前端框架、包管理器、搜索后端或必须运行的构建工具。
- 页面内容由 LLM 在 ingest/review 同步阶段按 Markdown 维护，索引是可再生成的静态派生文件。
- 可以用小型本地检查脚本验证链接、锚点和索引完整性，但用户打开网页不需要运行脚本。
- 不从外部 CDN 加载字体、图标、渲染器或搜索资源，保证核心功能离线可用。
- 静态搜索数据只从当前知识库产生，不读取本地浏览器历史等无关资料。

### 11.3 完整笔记出口

当前 `../../wiki/...md` 在本地存在，线上是否被站点根目录暴露尚未验证。第一版采用明确的可用出口：

- 每篇首屏提供“完整笔记”入口，指向 `site/notes/<分类>/<同名>.html`。
- 完整阅读页忠实转换 Markdown，不重新摘要，不删掉用户原话、来源限定和假说标记。
- 完整阅读页与速览共用排版和来源组件，减少独立样式维护。
- 搜索中未被速览收录的段落可直达完整阅读页。
- 保留原 Markdown 相对链接作为源文件入口；Zotero 深链接继续保留。
- 代码中的 `<box>` 等符号必须转义；公式可以保留可读的原始表示，不为此引入外网依赖。

这会增加九个派生完整阅读页的同步工作量。实施时必须通过完整性检查保证正文和锚点没有漏项；该成本是为稳定的全文阅读和段落搜索出口服务。

### 11.4 同步规则

| 变化 | 必须同步 |
|---|---|
| 新增／删除／重命名知识页 | 索引、速览、完整阅读页、静态索引、关联目标、日志 |
| 修改机制、问答或边界 | 对应速览与完整阅读页、搜索段落、受影响的关系说明 |
| 修改关系或证据状态 | 关系卡、反向引用、比较内容、搜索索引 |
| 更新复测 | 当前状态投影、历史提示的日期语境、必要的问答内容 |
| 修改 CSS/JS | 所有使用该资源的 HTML 的缓存版本串同步更新 |

HTML 与静态索引不能成为新的事实来源。发现重复内容冲突时，先回到 Markdown 的当前记录；记录本身矛盾时呈现待核对状态，不让前端挑一个看起来更合理的答案。

## 12. 现有规范的必要调整

本 spec 描述下一版目标，不自动覆盖当前 [CLAUDE.md](../../CLAUDE.md)。实施前应在用户授权的改造范围内同步以下规则；本次不修改它。

注意：当前 `AGENTS.md` 是指向 `CLAUDE.md` 的符号链接，应修改实际文件并保留链接，不能写成两个独立版本。

| 当前约定 | 下一版目标 |
|---|---|
| 每篇五至八张 slide | 连续阅读章节，按内容决定长度，必须保留卡壳点 |
| 首页按文件类型分组 | 问题专题优先，类型作为辅助筛选 |
| 上一篇／下一篇按索引连环 | 返回路径、语义目录和有解释的关联导航 |

| 共享 CSS、零构建、离线使用 | 继续保留 |
| Markdown 真源、费曼门槛、Zotero 锚点 | 继续保留 |

`index.md`、论文／概念／代码模板以及会实际读取旧滑页约定的 ingest/review 指令也应同步，避免下一次入库又生成旧结构。只改受这次站点迁移影响的条款。

## 15. 决策、风险与完成定义

### 15.1 已选定的方案

- 默认连续阅读，取消强制幻灯片结构。
- 首页采用问题专题与全文检索，文章类型作为辅助元信息。
- 标签维度受控，关系带理由与证据状态。
- 第一版优先局部关系和两篇比较，全局知识图后置。
- 复测真源继续在 Markdown，浏览器只提供阅读与练习交互。
- 保留静态、离线、无构建框架和现有部署路径。
- 首先验证 U-OPSD 与 S²VOPD，再迁移全部页面。

### 15.2 主要风险与处理

| 风险 | 处理 |
|---|---|
| 提醒太多，重新失去重点 | 限制最高级强调数量；关系优先两至三条 |
| 标签越来越散 | 使用词表与别名；按查找用途增加，定期合并重复名称 |
| 索引、速览、全文不同步 | 同一次内容更新完成同步，用路径、锚点和章节完整性检查兜底 |
| 旧问答状态过时 | 保留历史日期，当前状态来自 review.md |
| 自动关系放大推测 | 每条关系注明依据，个人解释保留待验证标记 |
| 试版影响旧页 | 新样式按阅读页作用域增补，旧页分批迁移 |
| 零构建方式增加人工簿记 | 由 LLM 统一维护派生文件，先用九篇验证成本，再决定是否需要独立生成工具 |
| 发布夹带其他任务修改 | 执行部署前检查全工作区与暂存区，明确本次文件范围 |

### 15.3 完成定义

全部九篇已迁移；索引、标签、关系、搜索、完整笔记和复测状态一致；验收矩阵中第一版项目通过或明确记录环境限制；用户实际完成“查一个困惑、读完一个机制、比较两篇文章”三个任务；维护规则能使下一次入库继续生成新结构。

本次 spec 的完成不代表上述产品改造已经完成。
