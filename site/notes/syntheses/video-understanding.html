视频理解与响应

看多少、何时想、怎样找证据？

专题本质

视频进入多模态大模型后有三笔账要算。第一笔是感知成本：帧率和分辨率一上去视觉 token 爆炸，LLM 注意力随序列长度二次方增长，长视频和实时流几乎跑不动，VideoChat3 在视觉编码器内压缩它。第二笔是思考时机：显式链式推理能提高多跳精度，但查询后再想会增加实时延迟，VST 把思考挪到查询前的播放空档。第三笔是证据获取：关键 2 秒藏在 10 分钟里，均匀采样会淹没证据；TSPO 训练 query-aware temporal agent 一次性选帧，Video-o3 查询后多轮裁剪搜索。

专题范围不覆盖视觉编码器本身的预训练，也不覆盖检测定位侧的 LocateAnything。这里的关系记录只组织四篇已入库论文，不把组合设想写成实验结论。

问题与方法地图

三条分支并列，不表示先后。证据获取分成两条路线：TSPO 用离线训练后的 selector 在回答前选帧，Video-o3 在查询后使用共享上下文和工具循环搜索。

视频理解
├── 感知成本 → VideoChat3：编码器内压缩与自适应分辨率
├── 思考时机 → VST：边看边想与 FIFO 文本记忆
└── 证据获取
    ├── TSPO：训练 temporal agent 选择 query 相关关键帧
    └── Video-o3：共享上下文内多轮裁剪找线索并作答

分叉与演进

  • VideoChat3：在编码器内消化时空冗余，留下短视频收益有限、小尺度证据可能看不见。
  • VST：把推理从查询后挪到播放期，留下 FIFO 有损和额外后台 token。
  • TSPO：把离散选帧与语言回答放进联合策略，用答案奖励和目标片段比例训练 selector，留下冻结 MLLM 依赖、1 FPS 候选限制和整体理解收益较小。
  • Video-o3：在共享上下文内交错工具调用与推理，留下轮数、上下文和工具种类上限。

跨篇卡壳点

VST 和 Video-o3 的推理时机分别放在哪里？

VST 在查询前边看边想，Video-o3 在查询后多轮调工具找线索。两个延迟数字的前提不同，不能直接比大小。

VideoChat3 的 token 压缩和 VST 的文本记忆是同一件事吗？

不是。前者管视觉感知效率，后者管推理时机和文本记忆。

VST 与 Video-o3 组合除了证据冲突还会引入什么问题？

查询即答与多轮探索后答在响应时机上冲突，需要统一调度。

TSPO 中答对的一组帧是否意味着每一帧都真正有用？R_T 是 IoU 吗？

不意味着。R_A 只说明整组帧足以答对，R_T 是目标片段内选帧比例，更接近 precision，而不是完整 IoU。Video-MME 只是收益较小，不是完全失效。

VST 的流式注意力掩码与 Video-o3 的 TDAM 是否解决同一类问题？

库内对照 VST 掩码把训练可见性对齐到流式推理，TDAM 按任务阶段限制全局与局部证据的可见性，不能直接归为同一种机制。
