蒸馏与训练预算

教师凭什么能教，多个教师又该怎样分配训练预算？

前两篇在自蒸馏里构造师生信息差（U-OPSD 给教师加一条自投票轨迹，S²VOPD 从学生减清晰像素），第三篇回答多个教师同时教时训练预算怎么分（Open-MOPD 证伪教师冲突、定位三层预算错配）。

跨专题
1 篇：PPO（理解 Open-MOPD 机制三的前置，主归属仍是强化学习与对齐）

信号只在自蒸馏里需要靠信息差制造：U-OPSD 给教师加一条自投票出的完整轨迹，S²VOPD 从学生减掉清晰像素，Open-MOPD 则是不同域专家教师之间的预算分账问题，不靠额外输入制造差异。

on-policy 蒸馏自蒸馏多教师蒸馏训练预算减少外部监督提高训练预算利用率

问题与方法地图

02

专题分成两个子问题。左侧「信息差从哪来」只针对自蒸馏设置（师生共享参数时必须靠额外信息差制造学习信号，否则分布相同、KL 为零）；Open-MOPD 的教师是不同域专家，不靠额外输入制造差异，属右侧的预算分账。PPO 以虚线连到 Open-MOPD，只表示理解前置，不表示论文继承。

边说明证据
蒸馏 → 教师凭什么提供更有用的分布单教师 OPD 的共同前提：师生分布必须有信息差，否则 KL 恒为 0，没有学习信号库内对照
蒸馏 → 多个教师的训练预算如何分配多教师 OPD 的独立问题：即便每个教师都合格，合并训练仍会掉分库内对照
信息差来源 → U-OPSD教师上下文里多拼进一条多数投票出的完整解题轨迹 y+，学生只看题目与答错前缀原文报告
信息差来源 → S²VOPD教师看原图、学生看降采样加噪的退化图，不对称来自减少学生的信息原文报告
预算分配 → Open-MOPD掉分主因是 token 份额、reward 幅度、reward 新鲜度三层预算错配，三个机制逐一修复原文报告
PPO ⇢ Open-MOPD机制三 reward refresh 建立在 PPO 的重要性比率与 clip 之上，不理解 clip 就看不出「75.8% 预算被冻结」的含义原文报告

分叉与演进

03

谱系背景来自 U-OPSD 页的自述，每往右一步去掉一类外部依赖；灰色虚框节点尚无独立页，只作背景，不是本库核实的方法继承链。

OPD要外部更强教师

图注：U-OPSD 与 S²VOPD 并列而非先后，是同作者线在两个域的域互补。

U-OPSD

原先瓶颈
OPSD 的教师仍要多看 GT 解，信息仍来自模型之外；GT 标注的成本与稀缺是规模化瓶颈。
本文改变
模型自己多数投票出的完整解题轨迹当教师特权上下文，只在答错 rollout 上逐 token 前向 KL。
仍留下
伪标签 13.3% 出错构成性能硬上界；只在可抽取最终答案的竞赛数学上验证。

S²VOPD

原先瓶颈
特权信号（更强模型、GT 答案、GT 区域）越来越难获得，特权方法还偏科。
本文改变
不对称不必给教师加信息，可以从学生减信息：学生看退化图，EMA 教师看原图。
仍留下
增益依赖增强调参（gap 大小与 task-consistency 双准则）；OCR 等细粒度任务预期失效是本人推演，论文未验证。

Open-MOPD

原先瓶颈
naive 多教师合并只拿回 35.6% 的提升，掉分被归咎于教师冲突。
本文改变
三重检验证伪教师冲突，定位到 token 份额、reward 幅度、reward 新鲜度三层预算错配并逐一修复，回收率到 83.4%。
仍留下
仅 3B 规模、三个域、oracle 真实标签路由；路由有误的场景未验证。

方法继承：未核实三篇之间存在明确的借鉴、替换或扩展关系（U-OPSD 与 S²VOPD 是同作者线的域互补，不是一篇改进另一篇），因此图中不画继承箭头。

跨篇卡壳点

06

U-OPSD 与 S²VOPD 的散度消融为什么完全相反？（S²VOPD 页 2026-09-02 首验、09-07 复测收敛）

先确认「相反」指什么：U-OPSD 必须 forward KL（reverse KL 复读崩溃、JSD 掉 13.8）；S²VOPD 是 JSD 最好 > reverse KL > forward KL 最差。实验事实到此为止，两组条件不同，不是一篇推翻另一篇。

待验证假说 库内解释：教师多出的信息学生能否恢复。U-OPSD 教师多的是解题思路，学生原则上自己能推出来，全面模仿（mode-covering 的 forward KL）方向正确；S²VOPD 教师多的是清晰像素，糊图里丢掉的细节拿不回来，forward KL 逼学生模仿接触不到的细粒度分布反而有害。量级佐证：U-OPSD 选错散度是灾难（13 点以上或崩溃），S²VOPD 选错只是小亏（1.3 点）。

y+ 是伪标签吗？（U-OPSD 页 2026-08-19 首验；S²VOPD 页 09-02 两连犯口误，09-07 复测收敛）

不是。y+ 是拼进教师输入的一条完整解题轨迹（几百到上千 token），整条喂教师、不截断；共识答案 ã(x) 才是单值，只用来投票和分组。消融 label-only（只给教师 boxed 答案值）掉 10.3~15.8，因为只知道答案值无法在每个 token 上指引「怎么走到这个答案」。跨篇高频复发点：读 S²VOPD 对照表时最容易把「教师多看的东西」又说成标签。当前状态：09-07 复测首答即明确，不再是弱项。

reward refresh 为什么零开销，又为什么修不掉全部陈旧？（Open-MOPD 页 2026-09-07 复测二次深化）

每个 token 的 dense reward 是教师 logprob 减学生 logprob。教师冻结，rollout 时一次算好缓存；学生当前 logprob 是 PPO 每次内更新算重要性比率本来就要 forward 出来的数，refresh 只是把这个已在显存里的数顺手填回奖励公式，不加教师 forward、不加学生 forward、不重新生成。修不掉的部分是轨迹本身仍由旧学生采样，换它要重新 rollout（生成占一步 46.5%，最贵），交给 PPO 的 ratio 与 clip 兜底。不刷新的代价：K=4 时 75.8% 的 token 被 clip 冻结。PPO 前置见 PPO 卡壳点。

待讨论（2026-09-09 本专题新提）：把多个 U-OPSD 式自蒸馏伪教师放进 Open-MOPD 的多教师框架，预算错配会以什么形态出现？

待验证假说 库内没有答案。两页关联节都说组合方案「成立」，但只论证了机制正交（教师从哪来 vs 预算怎么分），没有实验。可以确定的前提：Open-MOPD 的三层错配都以各域响应长度、收敛速度、K 次复用为条件，与教师是否自蒸馏无关；不确定的是自投票门控会按题跳过训练步，可能改变各域实际贡献的 token 份额。已记入 questions.md，等有实验或新论文再讨论。

EVIDENCE

待验证假说「信息可恢复性决定散度选择」（S²VOPD 页已声明，待 DistiLLM 系列入库验证）；「OCR 等细粒度任务上 S²VOPD 预期失效」（本人推演）；「多个自蒸馏伪教师组合后的预算形态」（本页新提，待讨论）。理解检验通过的假说仍是假说。
